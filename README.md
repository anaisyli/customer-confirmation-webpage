# 客户确认网页 Skill 使用说明

这个 Skill 把需要客户决定的事项做成一个**单文件、离线可打开的 HTML 网页**。客户能看到问题、原件参数、标亮截图和来源位置，直接选择或填写意见，再导出反馈。客户不需要登录系统，也不需要自己翻知识库里的 PDF、Word 或 PPT。

## 一眼看懂文件怎么流转

```text
知识库专员/经办人准备 CUS 问题和原件
        ↓ 用本 Skill 生成
客户确认页.html + 内部交接材料
        ↓ 只把 HTML 发给客户
客户打开、填写、导出
        ↓ 客户把反馈文件发回经办人
经办人收齐后转交知识库专员（你）
        ↓ 核验原答与证据，再决定是否更新 CUS、整理页和正式知识库
```

**发客户：** 通常只发 `交付客户/<项目>-客户确认页.html`。网页里的截图已嵌入，不需要把整个生成目录、源资料、截图文件夹或知识库发给客户。

**客户回传：**

- 如果后续要写回 `compile-enterprise-knowledge` 流程，优先让客户导出并回传 **CSV**，它使用《客户确认表.csv》的列名和编号格式。
- 如果客户需要跨设备续填，先导出 **JSON**，在另一台设备打开网页后点“导入已填反馈”；最后完成后建议再导出 CSV 回传。
- JSON 保存结构化选择、填写人和备注，适合留档；CSV 更适合知识库专员导入现有客户确认表。若经办人收到了两种文件，应一起转交，注明哪一个是最终版本。

## 谁做什么

### 知识库专员（问题和证据的负责人）

1. 从 `05_数据与审核/.../01_待客户补充事项.md`、构建目录的 `04_知识库构建/客户确认表.csv` 或指定问题清单中，筛出**已决定要问客户**的事项。内部仍待你决定的问题先不要混进客户版；如果负责人明确要求也交客户决定，就按要求纳入。
2. 对照每个来源原件，写明客户看得懂的问题、原件中的冲突值、具体产品/型号、原文件名和页码/表格行/章节。不能只给一个文件名或让客户去找“第几页”。
3. 为每一项截取清晰、紧凑但有上下文的原件证据图，把待确认字段用醒目框或浅色标亮。截图要保留相邻字段标题和表头。检查图像位置、清晰度、裁切、客户无关的敏感信息；不得改动原件。
4. 定义每个问题的选择项及需要补填的字段。允许“保留原写法 / 采用版本A或B / 按我填写的内容修改 / 暂不使用 / 还需内部确认”等适合该问题的选项，不要给所有问题强行套同一组选择。需要客户确认型号、单位、适用配置时，把这些做成明确字段。
5. 填写 `work/questions.json`（格式见 [references/data-schema.md](references/data-schema.md)），运行构建脚本，逐项浏览最终 HTML。校验事项编号和当前 CUS 台账一致，所有页面都有正确截图和来源位置。
6. 把**只有最终 HTML**发给客户；保留生成输入、原件/截图、构建报告和 HTML 修订版用于内部核验。不要把答案自动写进知识库。

### 经办人 / 资料整理同事（也可以自己用本 Skill）

如果你不是知识库专员，也可以用本 Skill 生成网页，但要取得知识库专员给出的：

- 已批准对外询问的事项和稳定 CUS 编号（不要自行新编或改编号）；
- 原始资料文件或经核实的原件截图；
- 每项问题的背景、可以提供给客户看的说明及希望客户回答什么；
- 反馈要写回哪个项目和知识库运行目录的约定。

如果没有源原件或不能确认截图与问题对应，先把缺项交回知识库专员，不要凭摘要拼造证据。经办人把 HTML 发客户后，应收回客户导出的最终反馈文件，并一并转交知识库专员；不要自行改台账为“已解决”，也不要把客户的推测性回答当作已核实参数。

### 客户

客户只需按经办人附带的简短说明操作：

1. 下载并用 Chrome、Edge 或其他现代浏览器打开 HTML 文件。
2. 看每项的原始参数和黄色标亮的截图；点击截图可以放大。
3. 选择处理方式。若选择修改，填正确数值、单位、型号或适用范围；不确定就选“还需内部确认”并说明。
4. 点“检查填写结果”，核对后导出反馈文件。
5. 把导出的反馈文件发回经办人。进度只保存在当前浏览器；要换设备继续时，先导出 JSON 并在另一设备导入。

## 经办人发给客户的消息模板

> 您好，请打开附件《<项目>-客户确认页.html》。页面列出了需要您确认的产品资料，并附有对应原件截图和标亮位置。请逐项选择；需要修改时请填写正确型号、参数和单位；暂时无法确认的项目可以标记“还需内部确认”。完成后点击“导出反馈”，并将下载的文件回复给我们即可。无需另行查找原文件页码。谢谢。

如果附件过滤系统不允许传 `.html`，经办人先询问公司允许的传递渠道或文件类型，不要擅自改成外网托管，也不要把知识库/整个运行目录打包。

## 可直接复制使用的 Prompt

### 知识库专员自己生成

```text
使用 $customer-confirmation-webpage 为 <客户/项目 ID> 生成客户确认网页。

输入：
- CUS 台账或当前运行目录的客户确认表：<完整路径>
- 原始资料/可访问的初筛包：<完整路径>
- 允许询问的 CUS 编号：<编号清单；如明确让客户决定内部保留项也在此说明>
- 新运行目录：<完整路径>

逐项重新核对原件。每个问题都要有客户看得懂的问法、可执行的选项、原文件名和精确位置，以及能看清字段/上下文的原件截图并标亮疑点。不要推断正确参数，也不要把未批准询问的内部问题加进客户版。生成单文件离线 HTML、问题 JSON、截图证据和构建报告；只把 HTML 放在交付客户目录。测试全部问题、截图、反馈 JSON/CSV 和手机布局。不要发送给客户或修改/发布知识库。最后告诉我：发给客户哪个文件、客户回传哪个文件、内部保留哪些材料。
```

### 经办同事用已整理好的证据生成

```text
使用 $customer-confirmation-webpage 把以下已批准事项做成可发客户的单文件离线 HTML。

项目 ID/客户名：<...>
问题清单和固定回答编号：<文件路径或粘贴内容>
每项原件截图（已高亮）及原文件名/页码：<路径和映射>
新输出目录：<完整路径>

不得新增或变更知识库专员给定的事项编号；不得根据截图自行改事实。检查截图与问题一一对应、每个问题和选项通俗易懂、CSV 导出保留原编号和指定列头、JSON 可以续填。生成后测试网页，并列出应发给客户的唯一 HTML，以及客户应回传的反馈文件。不要发送消息或改知识库。
```

### 经办人把客户回复交回知识库专员

```text
以下是客户对 <项目 ID> 的最终反馈，请作为待核验材料交给知识库专员，不要直接改正式知识库。

网页修订版：<客户打开的 HTML 文件名/修订号>
客户回传 CSV：<完整路径>
客户回传 JSON（如有）：<完整路径>
客户另附的新版规格书/图片（如有）：<完整路径>

请逐项对照 CUS 编号、客户原话和源证据，标出明确答复、部分答复、互相矛盾或仍待确认的事项；保留客户原文件，列出建议更新位置与需要人工确认的解释。未经知识库专员核验，不要写成已确认或发布。
```

## 知识库专员收到反馈后

1. 收客户返回的原始 JSON/CSV 文件、准确的 HTML 修订版标识，以及任何新的规格书/附件。让经办人说明反馈文件是否为最终版本；保留原始文件，不覆盖。
2. 核对每个反馈行的 CUS 编号、问题、选项、填写值、填写人/备注和证据版本。空答、选项与补充参数不一致、单位缺失、回答适用范围不清楚、客户新文件与答复不一致时，保持待确认并向经办人提出澄清。
3. 如果用 `compile-enterprise-knowledge`，把最终 CSV 副本按 `apply_answers.py` 的要求对照本次构建的 `04_知识库构建/客户确认表.csv`：**只将客户已填写内容写回匹配 CUS ID 的回答列**，保留原列头和编号。先检查 `governance.json` 中这些 CUS 项的答复类型；自由文本、型号/参数判断通常要由人审核，不能假设 `apply_answers.py` 会自动将其变成产品事实。运行该 Skill 的 `apply_answers.py` 后检查 `client-notes.jsonl`、未识别项和配置差异，再重跑、审核、按用户授权发布。
4. 仅当客户给出的明确事实能由指定型号/配置的答复支持时，更新整理页并链接回原始证据。若客户承认数值就是原件写法但不表示参数本身正确，记录其确认边界，保留必要风险标记。
5. 更新 CUS 处理记录，注明客户答复原文、日期、核验结果、作用范围和更新的页面。把仍缺视觉核验或仍待客户/内部确认的事项留在相应台账。

## 输出内容及用途

| 文件 | 谁使用 | 用途 |
|---|---|---|
| `交付客户/<项目>-客户确认页.html` | 客户 | 唯一需要发给客户的文件；离线显示问题和内嵌截图，收集并导出反馈 |
| `work/questions.json` | 知识库专员/经办人 | 页面源数据；保留问题、选择项、字段、编号和证据映射。不要发客户 |
| `work/evidence/` | 知识库专员/经办人 | 高亮原件截图；用于复核和更新，不单独要求客户另找/回传 |
| `内部交接/build-report.json` | 知识库专员/经办人 | 输出哈希、事项数、证据截图哈希，用于确认交付修订版 |
| `客户导出的 JSON` | 知识库专员 | 结构化反馈，可续填/导入原网页，适合追溯 |
| `客户导出的 CSV` | 知识库专员 | 一行一个编号的答复；列头与知识库客户确认表兼容，适合写回复制到现有构建表 |

不要把 `work/`、运行目录、初筛包、知识库或原始资料全发客户。只有在客户的答复引用了另一份文件或明确说会另附新版时，才要求其一起回传那份资料。

## 常见用法

从 [references/data-schema.md](references/data-schema.md) 复制或准备 `questions.json`，证据图放同目录的 `evidence/` 子目录：

```powershell
python "<skill-root>\scripts\build_review_page.py" `
  --data "<项目运行目录>\work\questions.json" `
  --output "<项目运行目录>\交付客户\<项目>-客户确认页.html" `
  --report "<项目运行目录>\内部交接\build-report.json"
```

无需额外 Python 第三方包。脚本会把 PNG/JPEG/WebP/GIF 证据图片内嵌到 HTML，并生成哈希清单。**建页后仍须用浏览器逐项视觉核查。**

# 离线决策网页 Skill 使用说明（客户确认 / 内部待办）

本 Skill 将需要决策的事项打包成**单文件、离线可打开的 HTML 网页**（证据图片全部内嵌，无需登录、无需翻原件）。按使用对象分为两种**校验与目录硬隔离**的模式，避免内部材料误发给客户。

---

## 一、先选模式

| 维度 | 客户确认模式（`--mode customer`，默认） | 内部待办模式（`--mode internal`） |
|---|---|---|
| **给谁用** | 客户（由经办人或专员发送） | 知识库专员（仅内部团队） |
| **解决什么** | CUS 事实核对、资料/图片公开授权、补交原件 | MAT / ANM / TERM / D / CUS 内部批量分流与决断（如尺寸图归属、词项放行、风险保留、决定哪些转 CUS） |
| **输出位置** | `交付客户/<项目>-客户确认页.html` | `内部决策/<项目>-内部待办决策页.html`（脚本**禁止**写入 `交付客户/`） |
| **导出文件** | 客户反馈 JSON + 兼容《客户确认表.csv》的 CSV | `governance-decisions.json`（`governance-decisions.v1`） |
| **怎么回填** | 经办人回收 → 专员核验 → `apply_answers.py --dry-run` 预演后回填 | 专员校验预览 → `governance_state.py collect --dry-run` → 增量重跑 |
| **安全红线** | 强行剥离内部备注和本地/知识库路径，只留初筛包相对路径 | 顶部固定警示 **「⚠ 内部审核专用 · 严禁发给客户」** |

---

## 二、场景 A：给客户做确认网页（`--mode customer`）

### 1. 文件怎么流转

```text
知识库专员/经办人准备已批准的 CUS 问题与原件
        ↓ 用本 Skill（--mode customer）生成
交付客户/<项目>-客户确认页.html + 内部交接材料
        ↓ 只把唯一 HTML 发给客户
客户在浏览器打开 → 选择/填写 → 导出反馈（JSON / CSV）
        ↓ 客户发回经办人 → 转交知识库专员
专员对照原件与修订版核验 → 按需更新 CUS、整理页和知识库
```

- **发客户**：只发 `交付客户/<项目>-客户确认页.html`，不要发 `work/`、运行目录、初筛包或知识库。若邮件系统拦截 `.html`，先确认公司允许的传递方式，不要擅自外网托管。
- **客户回传**：需对接 `compile-enterprise-knowledge` 时，CSV 保持《客户确认表.csv》列名和编号；如有案例替换、部分授权、审批待定或补充意见，请一并回传 JSON。客户需跨设备续填时，先导出 JSON 并在另一设备点击「导入已填反馈」。

### 2. 可直接复制的 Prompt（客户版）

#### ① 知识库专员自己生成（最常用）

```text
使用 $customer-confirmation-webpage 为以下项目生成客户确认网页：
- 知识库目录（或运行目录）：<完整路径；自动读取里面的 CUS 台账、客户确认表、官网快照与初筛包>
- 本次要问的 CUS 编号：<例如 CUS-001~005，或写“全部待汇总 CUS”>

逐项核对原件，生成客户看得懂的问法、选项和标亮证据截图；不要推断答案，也不要混入未批准的内部项。只把最终 HTML 输出到 交付客户/ 目录，完成全项与手机端测试。不要发给客户或改知识库，最后告诉我发哪个文件、客户回传什么。
```

#### ② 经办同事用已整理好的证据生成

```text
使用 $customer-confirmation-webpage 把我整理好的材料做成可发客户的离线确认页：
- 项目编号/名称：<例如 P-010>
- 材料目录或问题清单：<含问题、固定编号和原件截图的路径，或直接粘贴>

保持原有编号和事实不变，核对截图与问题一一对应、CSV 保留原编号和列头、JSON 可续填。只把最终 HTML 输出到 交付客户/ 目录并测试通过，不要发给客户或改知识库。
```

#### ③ 经办人把客户回复交回知识库专员

```text
把客户回传的确认结果交回知识库专员核验（不要直接改正式知识库）：
- 知识库目录（或运行目录）：<完整路径>
- 客户回传的文件（CSV / JSON / 新版附件）：<完整路径>

请对照 CUS 编号、网页修订版和原证据，标出明确答复、部分答复、矛盾项和待澄清项，保留客户原文件，等知识库专员核验后再决定更新。
```

### 3. 发给客户的话术模板

> 您好，请打开附件《<项目>-客户确认页.html》。页面列出了需要您确认的产品资料，并附有原始证据和标亮位置。请逐项选择；需要修改时请填写正确型号、参数和单位；暂时无法确认的项目可以标记“还需内部确认”。完成后点击“导出反馈”，并将下载的文件回复给我们即可。无需另行查找原文件页码。谢谢。

### 4. 客户版角色分工与核验要点

- **知识库专员（准备问题与证据）**：
  1. 只纳入**已决定问客户**的 CUS 事项，不要混入内部待定项；以当前客户确认表每一行作为独立答案，保留全部原编号和位置。
  2. 区分**事实核对**、**文件/图片使用授权**、**整份审批**与**补交原件**：授权题需标明原件名称/版本并附代表性片段，部分可用须必填章节、页码或限制；事实题附带上下文的高亮截图或官网摘录（标 URL 与取证/快照日期）。
  3. 生成后逐项浏览 HTML，核对 CSV 编号、原文件名、位置、答复类型与证据映射；保留输入 JSON、证据图、构建报告和 HTML 修订版留档。
- **经办人 / 资料整理同事**：
  - 须先从知识库专员获取已批准事项、稳定 CUS 编号、原始资料/核实证据及写回约定；不得自编编号或凭摘要拼造证据。
  - 收回客户反馈（如同时收到 JSON 和 CSV 须一并转交并注明最终版）交专员核验，不自行改台账或将推测性回复当已核实参数。
- **客户操作**：Chrome/Edge 打开 HTML → 查看原文/放大截图 → 选择并按需填写数值、单位或适用范围 → 点「检查填写结果」→ 导出 JSON/CSV 发回经办人。
- **知识库专员收到反馈后**：
  1. 保留客户原始 JSON/CSV、对应 HTML 修订版与新附件，不覆盖原文件。
  2. 逐项核对编号、选项、填写值、单位、适用范围及新旧文件一致性；缺单位、矛盾或范围不清的保持待确认并退回澄清。
  3. 对接 `compile-enterprise-knowledge` 时，可直接用 `apply_answers.py --answers <客户回传 JSON 或 CSV> --dry-run` 预演变更范围、未匹配旧编号与被拒资料的待清理缓存；自由文本和参数判断进 `client-notes.jsonl` 供人工审核，确认后再去掉 `--dry-run` 正式回填并按 `recommended_action` 刷新发布。
  4. 仅在明确事实有指定型号/配置答复支持时更新整理页并链接原证据；若客户仅确认“原件就是这么印的”但未确认数值本身正确，须保留风险标记。更新 CUS 处理记录。

## 三、场景 B：给内部做待办决策网页（`--mode internal`）

### 1. 文件怎么流转

```text
知识库目录（或本次建库运行目录）的 MAT / ANM / TERM / D / CUS 待办
        ↓ 用本 Skill（--mode internal）按根因聚合生成
内部决策/<项目>-内部待办决策页.html（顶部带「严禁发给客户」警示）
        ↓ 专员在浏览器按组决策（支持组内勾选/排除个别项、放大尺寸图）
导出 governance-decisions.json
        ↓ 交给 compile-enterprise-knowledge
核对预览 → governance_state.py collect → 增量重跑（如 --from guard）→ verify_kb.py
```

- **页面亮点**：首页顶部只按**待决事项组数**计待办，审计证据总数单列；已按规则自动结案（`autoResolved`）和已确认保留 ⚠（`riskRetained`）默认折叠在底部审计抽屉，不充数进待办；支持按台账筛选、一键预填未决推荐项、以及对词项/页码/尺寸图组内明细逐条取消勾选。

### 2. 可直接复制的 Prompt（内部版）

#### ① 知识库专员生成内部待办决策页

```text
使用 $customer-confirmation-webpage 的内部模式（--mode internal）生成内部待办离线决策页：
- 知识库目录（或运行目录）：<完整路径；自动读取台账、净化原文和缩略图/素材>

按根因把待内部决定项聚合成少量事项组（词项/页码/尺寸图放组内 members 支持整组采纳并取消个别项）；已自动结案的放 autoResolved，已确认保留 ⚠ 的放 riskRetained（默认折叠，不计入待办）；附带当前 CUS 概览。输出到 内部决策/（严禁写入 交付客户/），测试后告诉我页面路径、待决组数和审计证据数，不要改知识库。
```

#### ② 把导出的 `governance-decisions.json` 交回知识库校验应用

```text
使用 $compile-enterprise-knowledge 校验并应用这份内部决策文件：
- 导出的决策文件（governance-decisions.json）：<完整路径>
- 知识库目录（或运行目录）：<完整路径>

先核对项目、修订版与每组决定（含勾选/排除成员和备注），不要改原文件；先给我变更预览，确认后再执行 governance_state.py collect、按需增量重跑（如 --from guard）和 verify_kb.py，最后汇报剩余待决组数与新增待汇总 CUS。未经确认不要发布或发给客户。
```

## 四、目录结构与文件用途

所有产物保存在本机 `SEO-Runs` 根目录下的 `客户确认网页/<项目编号>-<项目名>/`（同一项目持续复用）：

```text
客户确认网页/<项目编号>-<项目名>/
├── 交付客户/                              ← 【唯一可发客户】
│   └── <项目名>-客户确认页.html
├── 内部决策/                              ← 【仅内部，严禁发客户】
│   └── <项目名>-内部待办决策页.html
├── work/                                  ← 【仅内部】输入 JSON 与证据图
│   ├── questions.json                     （客户版输入：customer-review-input.v1）
│   ├── internal-review.json               （内部版输入：internal-review-input.v1）
│   └── evidence/                          （高亮原件截图 / 缩略图）
└── 内部交接/                              ← 【仅内部】构建报告与归档修订版
    ├── build-report.json                  （客户页输出哈希与证据清单）
    └── internal-build-report.json         （内部页组数、成员数与证据清单）
```

> **浏览器导出的结果文件**：
> - 客户页导出：**客户反馈 JSON**（留档/续填）+ **CSV**（兼容《客户确认表.csv》，用于写回 `apply_answers.py`）。
> - 内部页导出：**`governance-decisions.json`**（仅内部，用于 `governance_state.py collect` 校验应用）。

## 五、命令行参考

无需额外 Python 第三方包；脚本会自动将 PNG / JPEG / WebP / GIF 内嵌为 Base64 并输出哈希报告。数据结构详见 [references/data-schema.md](references/data-schema.md)。**建页后仍须在浏览器中逐项视觉核查。**

```powershell
# 在本机的 SEO-Runs 根目录运行
$reviewRun = Join-Path '.' '客户确认网页/<项目编号>-<项目名>'

# 1) 构建客户确认页（--mode customer，默认）
python "<skill-root>\scripts\build_review_page.py" `
  --mode customer `
  --data "$reviewRun\work\questions.json" `
  --output "$reviewRun\交付客户\<项目名>-客户确认页.html" `
  --report "$reviewRun\内部交接\build-report.json"

# 2) 构建内部待办决策页（--mode internal，禁止输出到 交付客户/）
python "<skill-root>\scripts\build_review_page.py" `
  --mode internal `
  --data "$reviewRun\work\internal-review.json" `
  --output "$reviewRun\内部决策\<项目名>-内部待办决策页.html" `
  --report "$reviewRun\内部交接\internal-build-report.json"
```
